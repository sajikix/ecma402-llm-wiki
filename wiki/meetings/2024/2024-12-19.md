## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). TG2 agreed to bring the Unicode 16 numbering systems PR (#929) to the next TG1 and agreed that the `Intl.LocaleInfo` issues (fallback behaviour, `minimalDays`) should be fixed, with [FYT](../../people/FYT.md) to return with concrete proposals. TG2 was also open to dropping support for 5-8 letter language subtags as long as it does not break the web. Long discussions on the meaning of `"und"` and on `AvailableLocales` base-language requirements ended without a decision. [EAO](../../people/EAO.md) reported that the MF2 spec reached "final candidate" status and asked TG2 for feedback.

## Updates from the Editors

[USA](../../people/USA.md) said there are two PRs for the Stage 4 proposals. [SFC](../../people/SFC.md) announced the yearly update of the TG2 delegates list, with emails sent to those who attended two or more meetings this year.

## Define fallback behaviour

- wiki: [Intl Locale Info](../../proposals/intl-locale-info.md)
- proposal: [proposal-intl-locale-info#76](https://github.com/tc39/proposal-intl-locale-info/issues/76)

[HJS](../../people/HJS.md) said an implementer filed this from implementation experience and that interop requires minimising implementation-defined behaviour, with each field having a well-defined default. [FYT](../../people/FYT.md) argued the spec does not depend on CLDR and that fallback is unobservable and untestable. [SFC](../../people/SFC.md) agreed with the implementer's concern (compare `NumberFormat` falling back to the host locale rather than root), and said the expectation need not be normative but should be specified, possibly as implementation-defined.

## minimalDays #86

- wiki: [Intl Locale Info](../../proposals/intl-locale-info.md)
- proposal: [proposal-intl-locale-info#86](https://github.com/tc39/proposal-intl-locale-info/issues/86)

Several delegates ([SFC](../../people/SFC.md), [EAO](../../people/EAO.md), [HJS](../../people/HJS.md)) questioned whether `minimalDays` is motivated: it only matters for week numbering, which is ISO-based in practice (HTML `type=week`, Temporal's `weekOfYear`), and `firstDayOfWeek` has its own calendar-display use case. [FYT](../../people/FYT.md) countered that Java, PHP and .NET have it and that Mozilla had it as prior art; [SFC](../../people/SFC.md) noted the arguments for keeping it are Stage 3 status and prior art, while [HJS](../../people/HJS.md) and [USA](../../people/USA.md) said removal on user feedback should not be controversial. Related open questions: `"ltr"` versus `null` for unknown text direction, and reopening #90. Firefox's internal `minDays` is dead code.

## Should "und" behave like "root" or undefined? #885

- proposal: [ecma402#885](https://github.com/tc39/ecma402/issues/885)

Today all engines treat `"und"` as unavailable and fall back to the host locale. [SFC](../../people/SFC.md) said for `Collator` and `Segmenter` the locale is a property of the text, so host fallback is wrong. [USA](../../people/USA.md) said `undefined` already means host and that `"und"` could serve Intl-lite or [stable formatting](../../proposals/stable-formatting.md). [HJS](../../people/HJS.md) argued a literal `"und"` in `Collator` should mean root collation, while [ZB](../../people/ZB.md) distinguished undefined language, host locale, last-resort locale and a "non-locale" stable locale and preferred a heuristic of host, then last-resort, then stable; [EAO](../../people/EAO.md) noted [stable formatting](../../proposals/stable-formatting.md) had been considering `"zxx"` for this reason. No conclusion.

## Section 9.1 AvailableLocales shouldn't require base language if script is present #947

- proposal: [ecma402#947](https://github.com/tc39/ecma402/issues/947)

[SFC](../../people/SFC.md) said the spec requires `zh` if `zh-Hant` is supported and thought `zh` should mean `zh-Hans` or error rather than default to `hant`. [RGN](../../people/RGN.md) found it reasonable that in an environment supporting only `zh-Hant`, `zh` gives identical results, and [EAO](../../people/EAO.md) was persuaded that the spec should not define what `zh` means. No conclusion recorded.

## Document icu_locid's relationship to backwards compatibility syntax #3989

- proposal: [icu4x#3989](https://github.com/unicode-org/icu4x/issues/3989)

[ZB](../../people/ZB.md) listed discrepancies between ICU4X, test262 and ECMA-402 locale IDs: underscores, alias extensions, and 5-8 letter language subtags (e.g. `new Intl.Locale("posix")` is accepted by SpiderMonkey, JSC and V8), and proposed treating the latter as a bug. [SFC](../../people/SFC.md) supported fixing 402 to a strict subset ([EAO](../../people/EAO.md) pointed to the MF2 `lang tag` rule), while [HJS](../../people/HJS.md) and [EAO](../../people/EAO.md) wanted research or browser telemetry so as not to break the web. [SFC](../../people/SFC.md) will champion it if nobody else does. **Conclusion: TG2 is open to dropping support for 5-8 letter languages, either by exception or canonicalisation, but not if it breaks the web.**
