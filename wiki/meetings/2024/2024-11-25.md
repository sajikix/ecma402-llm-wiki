## Overview

Moderated by [SFC](../../people/SFC.md) (co-moderator). The notes file is dated 2024-11-25 but its own heading reads 2024-11-21. [LAF](../../people/LAF.md) attended only for part of the meeting. TG2 supported `Intl.DurationFormat` for Stage 4 (to go on the TG1 agenda), agreed to move forward with a century/two-digit-year option for the era display proposal, and supported [EAO](../../people/EAO.md) bringing currency symbol variants (#643) to TG1 as a Stage 1 proposal. Other topics (numbering systems for Unicode 16 in #929, `Intl.Locale.prototype.variants`, DisplayNames data slicing, Measure) were discussed without a final decision.

## Updates from the MessageFormat Working Group

[EAO](../../people/EAO.md) said the WG may be done: an issue audits whether to recommend the MF2 spec to CLDR-TC as non-preview, with the stability policy applying from CLDR 47. Next come an explainer and user guide, after which [EAO](../../people/EAO.md) will ask TG2 to review MF2 for fit-for-purpose; [SFC](../../people/SFC.md) suggested emailing the delegates list, with technical discussion in issues. [SFC](../../people/SFC.md) said the TG5 user study can only change MF2 at the edges and that TG1 delegates most hesitant about MessageFormat are aligned with the plan, so `Intl.MessageFormat` Stage 2 is plausible in 2025. [EAO](../../people/EAO.md) also highlighted late additions such as `:integer`, `:currency`, `:unit` (with `usage`) and `:math`.

## Updates from Implementers

[YSZ](../../people/YSZ.md) (JSC) had no feature updates, mostly bug fixing. [FYT](../../people/FYT.md) said V8 already shipped `Intl.LocaleInfo`, is removing old getters and is considering removing V8's break iterator. On timing for ES2025, [SFC](../../people/SFC.md) said Stage 4 in February is possible only if everything, including PR feedback, is fully resolved, and [BAN](../../people/BAN.md) and [RGN](../../people/RGN.md) agreed.

## Year precision #10

- proposal: [proposal-intl-eradisplay#10](https://github.com/tc39/proposal-intl-eradisplay/issues/10)

[SFC](../../people/SFC.md) described the ICU4X work on era display and asked whether to also control showing the century, with values like `"auto"`, `"full"` and `"withEra"`; ICU4C support should follow before a 402 proposal. [LAF](../../people/LAF.md) raised years before the common era and calendars that count backwards (Julian, and per [FYT](../../people/FYT.md) Taiwan-ROC), and favoured a `"numeric"` value; [RGN](../../people/RGN.md) observed the option rhymes with `NumberFormat.signDisplay`, and [EAO](../../people/EAO.md) was fine placing this under era display since a century is an era in the calendars in question. **Conclusion: good to move forward with centuries also handled by this option; investigate new option name and values.**

- wiki: [Intl.DurationFormat](../../proposals/intl-durationformat.md)
- proposal: [proposal-intl-duration-format#209](https://github.com/tc39/proposal-intl-duration-format/issues/209)

[BAN](../../people/BAN.md) was checking whether a large editorial PR based on MF's feedback is needed for Stage 4, and earlier test-coverage questions appear resolved since Anba closed the issue. ## Normative: Add 8 new numbering systems for Unicode 16 #929

- proposal: [ecma402#929](https://github.com/tc39/ecma402/pull/929)

[SFC](../../people/SFC.md) noted this PR recurs with each Unicode release and TG2 tries to keep the list current. [YSZ](../../people/YSZ.md) wanted to check with Apple's ICU folks first, since JSC uses system ICU (recently ICU 74) and it is hard to gauge timelines with people on vacation. [FYT](../../people/FYT.md) said merging into the spec would help push V8 to ship CLDR/ICU 76. Left open: [YSZ](../../people/YSZ.md) to give feedback for the January TG2 so it could go to TG1 in February.

## Why is there no Intl.Locale.prototype.variants? #900

- proposal: [ecma402#900](https://github.com/tc39/ecma402/issues/900)

[SFC](../../people/SFC.md) argued variants are one of the core subtag types and should have a getter. [ZB](../../people/ZB.md) and [FYT](../../people/FYT.md) questioned the use case (mostly Valencian Catalan, better expressed with a subdivision) and the getter's shape (array vs string, sorting), and [FYT](../../people/FYT.md) called variants practically deprecated. **Conclusion: questions remain about motivation and shape; continue discussing on the issue.**

## Display Names Data Slicing

- proposal: [icu4x#3260](https://github.com/unicode-org/icu4x/issues/3260)

[ZB](../../people/ZB.md) and [SFC](../../people/SFC.md) asked implementers for feedback on slicing `DisplayNames` data (across locales and across regions/languages), floating tiers such as "minimal", "core" and "extended". HJS was sceptical of any principled way to drop regions, since JS libraries already rely on browsers for region pickers, and shared usage numbers (region names dominate `DisplayNames` use) while suggesting historical currency names could go. [EAO](../../people/EAO.md) suggested tying completeness to `Accept-Language`, and HJS questioned why `dateTimeField` labels belong in the API at all. Open discussion, no decision.

## Add support for more currency symbol variants (e.g. formal) #643

- proposal: [ecma402#643](https://github.com/tc39/ecma402/issues/643)

[EAO](../../people/EAO.md), having implemented `:currency` in MF2, proposed a formal symbol (e.g. `US$` in `en-US`) and a `"never"` display value, but not the Turkish Lira variant. [SFC](../../people/SFC.md) questioned whether it is a `NumberFormat` option or a context option and how CLDR's "formal" differs from a wider symbol, and said it should be a (small) proposal rather than a PR. [EAO](../../people/EAO.md) asked to introduce it as Stage 1, with [SFC](../../people/SFC.md) and [BAN](../../people/BAN.md) supporting. **Conclusion: [EAO](../../people/EAO.md) to create a Stage 1 proposal and add it to the December TG1 agenda.**
