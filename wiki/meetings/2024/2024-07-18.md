## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). The editors announced that the ECMA-402 11th edition is approved and that [BAN](../../people/BAN.md) is to be made an official co-editor at the next TG1 plenary. Implementers reported `Intl.DurationFormat` progress in V8 and JSC, with [BAN](../../people/BAN.md) asking whether Stage 4 is plausible in October. [JMN](../../people/JMN.md) gave a Decimal-and-Intl check-in, [EAO](../../people/EAO.md) raised whether `Intl.MessageFormat` built-in functions should be exposed as static functions, and [FYT](../../people/FYT.md)'s `getWeekInfo()` fix for `Intl.Locale` info was narrowed to the uncontroversial part before going to TG1. No topic carries a formal Conclusion in the notes; outcomes are as stated per topic.

## Updates from the Editors

[BAN](../../people/BAN.md) said it has been slow, with most merges related to Temporal syncing. [USA](../../people/USA.md) announced that the ECMA-402 11th edition is approved and proposed that [BAN](../../people/BAN.md), who has worked as an editor for some time, officially join as co-editor; [SFC](../../people/SFC.md) agreed, noting [BAN](../../people/BAN.md) has been an apprentice editor for a year. It will be formalised at the next TG1 plenary.

## Updates from the MessageFormat Working Group

[EAO](../../people/EAO.md) said the WG has been quiet apart from an open ballot on normative requirements for error handling and fallback, which affects `Intl.MessageFormat` error handling (following the June Helsinki discussion; WG issues #830 and #831). [EAO](../../people/EAO.md) also described a WG discussion with Addison Phillips about which bidi marks to allow or recommend so right-to-left content works within the left-to-right syntax; [SFC](../../people/SFC.md) asked about UTS 55, and [EAO](../../people/EAO.md) agreed MF2 should be UTS 55 compatible.

## Updates from Implementers

[FYT](../../people/FYT.md) synced V8 to the latest `Intl.DurationFormat` spec, is staging it to Chrome 128 and plans to ask to ship in 129 (September), and is updating `Intl.LocaleInfo` to the current spec with getter removal in a later cycle. [BAN](../../people/BAN.md) asked whether `Intl.DurationFormat` Stage 4 in Tokyo (October) is plausible; [FYT](../../people/FYT.md) said it is possible but early, and [SFC](../../people/SFC.md) noted it would still make ES2025 (12th edition). [HJS](../../people/HJS.md) reported a pending patch for non-ISO calendars in Temporal by Anba, using ICU4X calendars. [YSZ](../../people/YSZ.md) said JSC is updating `Intl.DurationFormat` to the recently updated spec, which [SFC](../../people/SFC.md) welcomed as a sign V8 and JSC will interoperate.

## Decimal & Intl topic for the July Ecma 402 monthly call

- proposal: [ecma402#906](https://github.com/tc39/ecma402/issues/906)

[JMN](../../people/JMN.md) said Decimal is still moving and asked whether the Intl integration PR (mainly `PluralRules` and `NumberFormat`) is on the right track. [SFC](../../people/SFC.md) said that as of the previous day's review PR #173 did not yet achieve the intended Decimal-Intl integration and asked that editorial refactors be paired with the normative change that motivates them, as Anba does; [USA](../../people/USA.md) thought the work was already good enough for Stage 2. [EAO](../../people/EAO.md) asked whether `PluralRules` accepting `BigInt` (`NumberFormat` already does) needs a full proposal or can be a PR, and whether numbers with attached information (currency, units, fraction digits) should share a common input protocol. [SFC](../../people/SFC.md) and [USA](../../people/USA.md) said the `BigInt` change should start as an issue and then a PR, brought to TG1 and TG2, becoming a proposal only if it proves controversial; [JMN](../../people/JMN.md) is interested in doing it and [EAO](../../people/EAO.md) will sync offline. [SFC](../../people/SFC.md) suggested [Stable Formatting](../../proposals/stable-formatting.md), `Intl.MessageFormat` and the protocol idea as topics for an in-person session.

## What is the use case of resolvedOptions().functions ? #54

- proposal: [proposal-intl-messageformat#54](https://github.com/tc39/proposal-intl-messageformat/issues/54)

[EAO](../../people/EAO.md) wants the built-in formatting functions to be easy to reach so extension authors can wrap them, and prefers static functions such as `MessageFormat.number` and `MessageFormat.dateTime` over the currently hidden route through `resolvedOptions()`. [FYT](../../people/FYT.md) agreed with static functions on the class and did not want `resolvedOptions()` to return functions that implementations would have to wrap; [USA](../../people/USA.md) and [EAO](../../people/EAO.md) noted the invariant that `resolvedOptions()` output can be fed back into the constructor. [SFC](../../people/SFC.md) was uneasy about returning non-primitive values from `resolvedOptions()` and had not settled on a recommendation; [EAO](../../people/EAO.md) said removing `resolvedOptions()` altogether would be acceptable. [FYT](../../people/FYT.md) also asked whether customisation binds to a type or a variable, which was not resolved. Open: no decision was recorded.

## WeekInfoOfLocale need to convert loc.[[FirstDayOfWeek]] to number before return

- wiki: [Intl Locale Info](../../proposals/intl-locale-info.md)
- proposal: [proposal-intl-locale-info#82](https://github.com/tc39/proposal-intl-locale-info/issues/82)

[FYT](../../people/FYT.md) presented PR #83, which fixes the string-versus-number spec bug for `[[FirstDayOfWeek]]` but also bundles Anba's changes: hard-coding the first day for `-u-ca-iso8601` and using only `language_id` (so `-u-rg` is ignored until supported). [SFC](../../people/SFC.md) and [LAF](../../people/LAF.md) objected that the calendar can affect the first day of the week (for example Hebrew), that ICU may simply be buggy for `fr-u-ca-hebrew`, and that "implementation and locale defined" (ILD) wording should be used consistently ([SFC](../../people/SFC.md) filed an issue). [RGN](../../people/RGN.md) suggested making ILD a definition. Outcome: [FYT](../../people/FYT.md) will revert the `language_id` change and keep the integer conversion and the ISO 8601 check, and put that version of the PR on the TG1 agenda.
