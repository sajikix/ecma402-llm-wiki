## Overview

Co-moderated by [SFC](../../people/SFC.md), [USA](../../people/USA.md) and [RCA](../../people/RCA.md). TG2 agreed that Intl.Segmenter can proceed to Stage 4, approved a Locale Info PR (#49) and the "tnsa" numbering system PR (#614), and discussed how quickly ECMA-402 should follow ICU/CLDR. [Intl.DurationFormat](../../proposals/intl-durationformat.md)'s push for Stage 3 met pushback (Apple not yet prepared to give feedback, [FYT](../../people/FYT.md) thought the spec unfinished). [FYT](../../people/FYT.md) previewed a Segmenter v2 Stage 0 proposal, and transliteration and `Array.prototype.toLocaleString` with `ListFormat` were explored. The notes show a speaker `MGM` who is not in the attendee list and could not be mapped to a delegate (possibly a typo for [MCM](../../people/MCM.md)); the abbreviation is kept as written. Several PR sections (#613, #572, #571) are template placeholders with no recorded discussion and are omitted.

## Normative: Add new numbering system "tnsa"

- proposal: [ecma402#614](https://github.com/tc39/ecma402/pull/614)

[USA](../../people/USA.md) noted TG1 consensus is needed and asked whether to reference the Unicode table directly instead of updating manually; [SFC](../../people/SFC.md) pointed to the existing meta-issue (ecma402#584) about how to handle such CLDR-driven PRs. [YSZ](../../people/YSZ.md) noted the numbering system is not yet in a shipping ICU, so conformance would require ICU trunk; [FYT](../../people/FYT.md) answered that implementations have about nine months because the spec is published once a year, and that the table is the minimal set, not the maximal. [SFC](../../people/SFC.md) framed the meta-question of how far ECMA-402 should lag ICU/CLDR (e.g. wait for a stable ICU release). [MCM](../../people/MCM.md) said Apple would take it to release engineering and answer in the thread, and in the continuation stated a preference that the feature be removed from the spec while not blocking others from shipping it. **Conclusion: Approved** (recorded under the first discussion; the continuation records no separate conclusion).

## Temperature check for Support ICU transliteration in ECMAScript - rough draft #560

- proposal: [ecma402#560](https://github.com/tc39/ecma402/issues/560)

[SFC](../../people/SFC.md) brought it only as a temperature check. [FYT](../../people/FYT.md) said ICU transliteration is very generic and CLDR data quality varies, and suggested scoping to hiragana/katakana to Latin and Indic scripts to Latin; [MCM](../../people/MCM.md) favoured transliteration, noted data size and the need for interoperability with CSS `<ruby>`; [USA](../../people/USA.md) wanted a scoped design benchmarked on size versus usage. **Conclusion: the group needs to figure out the right way to shape this proposal.**

## Change Array.prototype.toLocaleString to use ListFormat #422

- proposal: [ecma402#422](https://github.com/tc39/ecma402/issues/422)

The default would follow `ListFormat`'s default. [FYT](../../people/FYT.md) volunteered a PR and acknowledged a compatibility change; [GPT](../../people/GPT.md) and [USA](../../people/USA.md) stressed web compatibility (output is non-deterministic and may vary with data); [YSZ](../../people/YSZ.md) asked about nested arrays, which the current implementation allows, and [MCM](../../people/MCM.md) said the change must make nested arrays work in `ListFormat`. **Conclusion: write a PR to modify the spec and validate whether there is any compatibility issue.**
