## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). TG2 approved PR #724 (canonicalise "GMT" to "UTC"), merged #708, and discussed User Preferences at length, with fingerprinting and permission granularity as the main concerns. The group was fine with decoupling Intl Era Display from Temporal, with [SFC](../../people/SFC.md) aiming for a Stage 2 proposal at the December TG1. For [Intl.DurationFormat](../../proposals/intl-durationformat.md), `format()` given a string should throw `RangeError` (strings only), and `formatToParts` use cases were opened. The notes end with the last item unfinished, and there is no conclusion for #715 or #714.

## User Preferences

- slide: [link](https://docs.google.com/presentation/d/1REfjL8HBfAQQoXzG69kk43ywuT2hW5SuJCNtYxWPAJk/edit#slide=id.p1)

[RCA](../../people/RCA.md) presented. [FYT](../../people/FYT.md) raised the latency cost of extra HTTP headers and argued TG2 has no concept of a user, so the JS API for settings is the relevant part and the rest belongs at W3C; [RCA](../../people/RCA.md) replied Client Hints are already defined at IETF and the proposal is already being pushed at W3C. [YSZ](../../people/YSZ.md) said Apple WebKit sees value but calls it a strong fingerprinting vector and leans towards asking user permission (for example a weather page asking for temperature units). [DLM](../../people/DLM.md) reported Mozilla's privacy team urged minimising the fingerprinting vector, exposing only what is needed and possibly at coarser granularity, and is willing to review a later draft. [SFC](../../people/SFC.md) compared the privacy model to cookies and doubted webcam-style permission prompts are meaningful. [FYT](../../people/FYT.md) wanted granular, per-setting access and a way to distinguish a user declining from a value, and suggested font and voice settings as candidates; [USA](../../people/USA.md) considered these out of scope. [EAO](../../people/EAO.md)'s "basket" idea (grouped preference sets) was said by [DLM](../../people/DLM.md) to echo the privacy team's suggestion, while [SFC](../../people/SFC.md) worried baskets would be hard to define. [RCA](../../people/RCA.md) asked [DLM](../../people/DLM.md) and [YSZ](../../people/YSZ.md) to open issues on the repo. **Conclusion: [RCA](../../people/RCA.md) to respond to the feedback from above.**

## Intl Era Display

[SFC](../../people/SFC.md) asked whether the proposal should depend on Temporal or be standalone. [USA](../../people/USA.md) favoured holding for Temporal but also wanted one single procedure to determine the era; [EAO](../../people/EAO.md) asked whether implementation-defined behaviour now could later be replaced by Temporal, which [SFC](../../people/SFC.md) confirmed is the way to decouple. [LAF](../../people/LAF.md) was fine with decoupling, and [SFC](../../people/SFC.md) read the group as agreeing, and said it is implementable on ICU4C and hopefully easier on ICU4X. [SFC](../../people/SFC.md) would like a decoupled Stage 2 proposal at the December TG1. **Conclusion: [SFC](../../people/SFC.md) to put the presentation on the TG1 agenda and mail it to this group.**

## tests depends on specific pre-ICU72 format pattern need to be changed #3711

- proposal: [test262#3711](https://github.com/tc39/test262/issues/3711)

[FYT](../../people/FYT.md) asked whether test262 tests that depend on ICU format patterns should be eliminated. [SFC](../../people/SFC.md) and [YSZ](../../people/YSZ.md) said it is hard to test features without depending on CLDR data (Apple's ICU is also slightly customised); [PFC](../../people/PFC.md) suggested test262 should ease implementations and fewer such tests may be better; [DLM](../../people/DLM.md) said the ICU 72 test changes caused little work. [FYT](../../people/FYT.md) suggested loosening checks (for example a "March" substring). **Conclusion: add this to the agenda in the Test262 maintainers call.**

## Throw RangeError instead of TypeError for format with non-object types #128

- wiki: [Intl.DurationFormat](../../proposals/intl-durationformat.md)
- proposal: [proposal-intl-duration-format#128](https://github.com/tc39/proposal-intl-duration-format/issues/128)

[USA](../../people/USA.md) introduced the issue. [YSZ](../../people/YSZ.md) argued that aligning with how Temporal handles a Duration (string input throwing `RangeError`) would ease later integration, keeping string parsing an empty syntax for now. [SFC](../../people/SFC.md) noted `DateTimeFormat` cannot change for web compatibility, so string handling would be specific to `DurationFormat`; [USA](../../people/USA.md) recalled a past TG2 consensus to expand to strings later, and [PFC](../../people/PFC.md) said Temporal entry points taking a Duration accept a property bag or a string. **Conclusion: `RangeError`, strings only.**
