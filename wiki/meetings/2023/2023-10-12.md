## Overview

Moderated by [SFC](../../people/SFC.md) (co-moderator). [BAN](../../people/BAN.md) will present the two approved [Intl.DurationFormat](../../proposals/intl-durationformat.md) PRs at the next TG1, and [SFC](../../people/SFC.md) added a "review TG1 agenda" item to the meeting template. TG2 agreed to advocate that the Intl.Locale first-day-of-week getter return the BCP 47 string, with `undefined` as a fallback if TG1 pushes back (#78). Locale Extensions bucketing should use CLDR data to inform the [amount](../../proposals/amount.md) of entropy without listing buckets in the spec, and [JGT](../../people/JGT.md) will draft a non-normative recommendation PR for time zone canonicalization (#825). Negative [Intl.DurationFormat](../../proposals/intl-durationformat.md) rendering was left unresolved. [JGT](../../people/JGT.md) spoke throughout but is not in the attendee list.

## Locale with `-u-fw-` value other than 13 value will cause assertion

- wiki: [Intl Locale Info](../../proposals/intl-locale-info.md)
- proposal: [proposal-intl-locale-info#78](https://github.com/tc39/proposal-intl-locale-info/issues/78)

Since TG1 asked for `firstDayOfWeek` to return integers 1-7 instead of strings, it is unclear what the getter should do for a syntactically valid but unknown `-u-fw-xyz` in a locale string (unlike the options bag, which throws). [SFC](../../people/SFC.md) listed options: throw in the constructor, echo the string, return the default first day, go back to TG1, or return `undefined`. SBE preferred throwing for developer insight, but [FYT](../../people/FYT.md) argued against it (`Intl.Locale` is GIGO for valid syntax) and [SFC](../../people/SFC.md) noted `-u-ca-mistake` already echoes back. [SFC](../../people/SFC.md)'s concrete fallback was `undefined` from the getter with `toString` keeping the input, but the group leaned toward going back to TG1: return the string like every other getter (getWeekInfo already returns the integer), with the `undefined` option as fallback, ideally after [FYT](../../people/FYT.md) talks with [DE](../../people/DE.md). [RGN](../../people/RGN.md), [BAN](../../people/BAN.md), [YSZ](../../people/YSZ.md) and [EAO](../../people/EAO.md) supported. No formal Conclusion in the notes; [FYT](../../people/FYT.md) will craft the TG1 proposal before November.

## Locale Extensions Update

[BAN](../../people/BAN.md) described two directions: exposing only the most common sets of options (similar to [MCM](../../people/MCM.md)'s font approach, which [BAN](../../people/BAN.md) is increasingly skeptical of), or allowing only three tags (`-u-hc`, `-u-nu`, `-u-mu`). [SFC](../../people/SFC.md) raised the combinatorial explosion, and [EAO](../../people/EAO.md) asked for data on common combinations. [YSZ](../../people/YSZ.md) said the feature is valuable (e.g. numbering system in Arab countries) but each additional value multiplies fingerprinting, so bucketing is preferred, with a fixed number of buckets left to each implementer; the Apple position on exposing this to servers (Client Hints) is open. [RGN](../../people/RGN.md) stressed that bucketing is separate from how values are expressed (e.g. a sparse side table of allowable buckets). **Conclusion: [BAN](../../people/BAN.md) to create example buckets based on CLDR data to inform decisions about how much entropy is needed; define the entropy in the specification but not the specific buckets.**

## Should ECMA-402 spec text for time zone canonicalization refer to CLDR or to IANA as authoritative? #825

- proposal: [ecma402#825](https://github.com/tc39/ecma402/issues/825)

[JGT](../../people/JGT.md) explained CLDR's ongoing fixes (e.g. Kyiv, Kolkata, a new IANA attribute) and asked what the spec should say: A, mandate CLDR; B, define behaviour in terms of IANA; C, B plus a note that CLDR/ICU provide it. [EAO](../../people/EAO.md), [RGN](../../people/RGN.md), SBE and [YSZ](../../people/YSZ.md) opposed normative requirements, since databases and build options legitimately differ; [SFC](../../people/SFC.md) said the spec should describe the desired outcome (canonical names such as Kyiv promoted after a timeframe), possibly with test262 tests, with CLDR and IANA only as examples. [JGT](../../people/JGT.md) argued that clear text protects the outcome if CLDR changes course. **Conclusion: [JGT](../../people/JGT.md) will draft a PR with a (non-normative) recommendation based on Option C for further discussion.**

## Draft plan to align canonical time zone IDs across implementations #806

- proposal: [ecma402#806](https://github.com/tc39/ecma402/issues/806)

[JGT](../../people/JGT.md) proposed using "primary"/"non-primary" instead of "canonical", treating every ID in `zones.tab` as primary (as CLDR has always done), and using the new ICU/CLDR IANA attribute to get e.g. `Asia/Kolkata`. [SFC](../../people/SFC.md) thought these details are better reviewed as a PR than an issue. On timing, [JGT](../../people/JGT.md) suggested waiting for Temporal to switch implementations to the new ICU API rather than doing it early; the two-year wait before adopting renamed IDs was recalled as an earlier TG2 recommendation. No formal conclusion.

## Format of Negative Durations

- wiki: [Intl.DurationFormat](../../proposals/intl-durationformat.md)
- proposal: [proposal-intl-duration-format#169](https://github.com/tc39/proposal-intl-duration-format/issues/169)

How should a negative (non-mixed) absolute duration render in [DurationFormat](../../proposals/intl-durationformat.md), given CLDR gives no clear signal? [SFC](../../people/SFC.md) listed options: sign on the first unit only, or on every unit; others suggested parentheses ([BAN](../../people/BAN.md), [EAO](../../people/EAO.md) found it the only unambiguous one), a key phrase like "earlier" ([JGT](../../people/JGT.md)), or falling back to `toString` ([FYT](../../people/FYT.md)). [SFC](../../people/SFC.md) favoured a sign on every unit and possibly taking a recommendation to CLDR; [RGN](../../people/RGN.md) was inclined toward a sign on the first unit only, or not specifying it yet, and warned the group might regret it. Examples given were flight-time deltas and chess timers. No decision; the group ran out of time.
