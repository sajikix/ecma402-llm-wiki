## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). TG2 gave consensus to raise the maximum fractional digits to 100 (#786, tentatively, pending [FYT](../../people/FYT.md) and [YSZ](../../people/YSZ.md) review of the added `Intl.Locale` getter) and to reorder the `roundingPriority` resolved option (#768, not blocked on test262), while #788 (UTC offset time zones) was held for the September TG1 because [RGN](../../people/RGN.md) was absent. The longest item was `Etc/Unknown` for unrecognised OS time zones (canonical-tz #25), which ended without consensus, followed by [JGT](../../people/JGT.md) previewing the canonical time zone proposal's Stage 3 request, where [FYT](../../people/FYT.md) objected to the current spec text. [USA](../../people/USA.md) also proposed a "Needs consensus" process, presented two [Intl.DurationFormat](../../proposals/intl-durationformat.md) PRs (#158, #150), and [FYT](../../people/FYT.md) and [SFC](../../people/SFC.md) settled that `getWeekInfo()` keeps numeric weekday values ([Intl Locale Info](../../proposals/intl-locale-info.md) #68). [BAN](../../people/BAN.md) gave a Locale Extensions update.

## Use Etc/Unknown (like ICU does) to handle the case when the OS's time zone is unrecognized by ECMAScript #25

- proposal: [proposal-canonical-tz#25](https://github.com/tc39/proposal-canonical-tz/pull/25)

[JGT](../../people/JGT.md) summarised the problem (an OS knows a zone ID such as the Kiev to Kyiv rename that the engine does not; SpiderMonkey and JSC silently give UTC, while Chromium returns `Etc/Unknown`, which cannot be used as input) and proposed making `Etc/Unknown` a first-class identifier. [YSZ](../../people/YSZ.md) objected to returning `Etc/Unknown` as output (input is fine): it is not in the IANA database, other tools such as Python and C++ reject it, and a working `UTC` fallback is preferable to a new crash; [YSZ](../../people/YSZ.md) suggested a separate API to detect an unrecognised zone. [FYT](../../people/FYT.md) noted the ID comes from UTS 35 and CLDR/ICU localise its display name, and [SFC](../../people/SFC.md) and [JGT](../../people/JGT.md) suggested UTS 35 as the place to standardise it; [JGT](../../people/JGT.md) argued that silent `UTC` sends wrong data too and that failing visibly without crashing is the better middle path. [SFC](../../people/SFC.md) asked what happens if the PR is not merged (behaviour stays implementation-dependent) and said the Stage 2 understanding was that this problem would be solved, so Stage 3 without fixing it is a concern. **Conclusion: [JGT](../../people/JGT.md): no consensus, the PR is not accepted and current behaviour of each implementation remains.**

[JGT](../../people/JGT.md) then previewed the canonical time zone Stage 3 request for TG1: stop canonicalising non-canonical inputs (compare with `Temporal.TimeZone.p.equals`), add canonicalization to `TimeZoneEquals`, and editorial prose for a waiting period (two years, taken from Android) before new IANA IDs become canonical; the part on converging implementations was dropped from the proposal. [FYT](../../people/FYT.md) rejected the current spec text, citing `SystemTimeZoneIdentifier()` and an `if` clause that bans sub-minute offsets, and worried about proposals needing many changes at Stage 3 (also citing [DurationFormat](../../proposals/intl-durationformat.md) and Locale Info); [JGT](../../people/JGT.md) expects the text to be caught up with Temporal before the Bergen plenary. [YSZ](../../people/YSZ.md) said "LGTM" and that Apple is generally supportive, as the change avoids random string comparisons. [SFC](../../people/SFC.md) deferred remaining concerns to Bergen.

## Intl.Locale Info discussion

- wiki: [Intl Locale Info](../../proposals/intl-locale-info.md)
- proposal: [proposal-intl-locale-info#68](https://github.com/tc39/proposal-intl-locale-info/issues/68)

[FYT](../../people/FYT.md) explained the plan to accept `-u-fw` as a relevant `Intl.Locale` extension key (uncontroversial), which raises adding a `firstDayOfWeek` option and creates a third weekday representation (`Date` counts Sunday as 0, Temporal and `getWeekInfo()` use 1-7, `-u-fw` uses three-letter codes). [SFC](../../people/SFC.md) preferred keeping Temporal-style numbers for `getWeekInfo()` (the two numeric schemes agree modulo 7) and noted there is no precedent when an ECMAScript representation differs from BCP 47's namespace, which could go to TG1; [JGT](../../people/JGT.md) favoured matching input and output. **Conclusion: [FYT](../../people/FYT.md) will remove the weekday-representation change from the PR and ask TG1 for consensus on the rest; a half-hour slot with TG1 in Bergen was proposed, and [SFC](../../people/SFC.md) will invite [ZB](../../people/ZB.md) to a call.**
