## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). The editors' update turned into planning for the ES2024 edition: the group agreed there is no rush and floated treating the February 2024 plenary as the cutoff, with [FYT](../../people/FYT.md) doubting [DurationFormat](../../proposals/intl-durationformat.md) or Intl Locale Info would reach Stage 4 in time. The meeting also brought the PR to take the `ignorePunctuation` default from locale data to TG1, heard an Intl eraDisplay update from [LAF](../../people/LAF.md) with a proposed set of values, agreed a fix for #707 (canonicalise keyword values in `ApplyUnicodeExtensionToTag`), and parked variant era names (#845). Compact notation with byte and SI units (#730, #810) was identified as largely a CLDR data problem, to be revisited with [Stable Formatting](../../proposals/stable-formatting.md) and the CLDR design group.

## Updates from the Editors

[RGN](../../people/RGN.md) had nothing to report beyond prefixing percent-quoted intrinsics with `Intl.`, expected to land before the next meeting. [SFC](../../people/SFC.md) and [USA](../../people/USA.md) noted it is time to plan the ES2024 artifact without the scramble of last year, reusing the process worked out then and contacting the ECMA-262 editors and Ecma staff. Discussing scope, [FYT](../../people/FYT.md) expected several normative PRs and no new proposals: [DurationFormat](../../proposals/intl-durationformat.md) still has editorial refactoring and tests outstanding, and Intl Locale Info has unresolved issues (`fw` resolution, calendar ordering; the `firstDayOfWeek` getters are TG1-approved but not yet merged). [USA](../../people/USA.md) suggested the editors set a cutoff, and [SFC](../../people/SFC.md) proposed that the February 2024 plenary be the deadline, with anything landing later left out of the release.

## Updates from the MessageFormat Working Group

[EAO](../../people/EAO.md) reported progress towards getting the whole spec out with the ICU spring release (ICU 75), with remaining blockers being chased. There is no consensus on the formatted-parts structure, so it will be specified in the Intl Message Format proposal's `formatToParts`; markup placeholders are close to final and will work like HTML tags (`#` and `/`), the function registry is nearly settled, and a second in-person meeting is planned after the San Diego TC39 meeting.

## Updates from Implementers

[FYT](../../people/FYT.md) had nothing new but described the CLDR 44 / ICU 74 situation: Mozilla backed out because a CLDR inheritance change interacted with an ICU hack that opted out of inheritance (breaking locales like `sv-SE`), Apple has signed up to fix the ICU bug, and nobody is moving to ICU 74 yet; [SFC](../../people/SFC.md) and [EAO](../../people/EAO.md) noted ICU 74.2 was in progress that week. [EAO](../../people/EAO.md) announced that `Intl.Segmenter` is now in non-nightly Firefox and is going to release, implemented on top of the ICU4X segmenter.

## Updates from the W3C i18n Group

[EAO](../../people/EAO.md) cannot attend all meetings but keeps in contact with members. In answer to [FYT](../../people/FYT.md), [EAO](../../people/EAO.md) confirmed Addison remains chair despite having retired from Amazon.

## Normative: Allow locale based ignorePunctuation default #833

- proposal: [ecma402#833](https://github.com/tc39/ecma402/pull/833)

[FYT](../../people/FYT.md) found while working on V8 that a Test262 test broke because CLDR and the spec differ: `ignorePunctuation` is false for most locales but true for Thai. [SFC](../../people/SFC.md) endorsed pulling such values from locale data as a well-structured Boolean and [EAO](../../people/EAO.md) gave +1. [SFC](../../people/SFC.md) judged this enough approval to take it to TG1 for consensus.

## eraDisplay Updates

- proposal: [proposal-intl-eradisplay](https://github.com/tc39/proposal-intl-eradisplay)
- slide: [slides](https://docs.google.com/presentation/d/1E52qRsTNoPyIJx8YesoPuz0ilfGT61X7Rnwj13Bdpz4/edit?usp=sharing)

[LAF](../../people/LAF.md) presented a proposed set of `eraDisplay` values (`void` for existing behaviour, `auto`, `discreet`, `explicit`, `always`, `never`). [FYT](../../people/FYT.md) noted other calendars (Minguo, Coptic) also number backwards eras from 1 and that ICU reuses the era field for Chinese/Dangi cycles. [SFC](../../people/SFC.md) wanted `auto` as the default rather than preserving the old behaviour, supported by [LAF](../../people/LAF.md) and [FYT](../../people/FYT.md), suggested a cutoff-date-based display (e.g. "763 AD" but "1600"), and questioned whether `explicit` and `always` should be separate. There was no objection to adding a `PatternEra` slot, as it only adds a single pattern string. No decision was recorded; [SFC](../../people/SFC.md) wants another update next month and then possibly a stage advancement request.

## ApplyUnicodeExtensionToTag and ResolveLocale set the result record's internal slots to non-canonical values #707

- proposal: [ecma402#707](https://github.com/tc39/ecma402/issues/707)

[FYT](../../people/FYT.md) could not find where the spec allows canonicalising extension keywords (only the LSRV is canonicalised), while [RGN](../../people/RGN.md) pointed to the processing rules in UTS 35; `ApplyUnicodeExtensionToTag` is used only in `Intl.Locale`, whereas the other constructors use the resolved locale. [EAO](../../people/EAO.md) said this does not affect `firstDayOfWeek`, as string forms are still needed. **Conclusion: Change step 5f in ApplyUnicodeExtensionToTag to canonicalize the keyword value. [FYT](../../people/FYT.md) volunteers to do it.**

## Add option to use variant era names #845

- proposal: [ecma402#845](https://github.com/tc39/ecma402/issues/845)

[LAF](../../people/LAF.md) suggested variant era names (e.g. for Julian-Gregorian or Islamic calendars); [EAO](../../people/EAO.md) asked whether AD and CE differ, and [RGN](../../people/RGN.md) said CE is merely an alias, while [LAF](../../people/LAF.md) argued AD/BC belongs to the Julian calendar and CE to the proleptic Gregorian. [SFC](../../people/SFC.md) preferred getting era display differences via the calendar system (`gregory`, `gregory-julian`, `julian`) rather than a new option. [SFC](../../people/SFC.md) proposed putting it on the backlog until Temporal, Era Code and Era Display have landed, and [LAF](../../people/LAF.md) agreed.

## NumberFormat has odd behaviour for narrow/compact display of bytes #730

- proposal: [ecma402#730](https://github.com/tc39/ecma402/issues/730)

[CDA](../../people/CDA.md) linked this to #810. [SFC](../../people/SFC.md) wondered whether compact notation with `style: "unit"` should select the correct unit for specific sets; [RGN](../../people/RGN.md) thought it is mainly a missing whitespace (a CLDR bug to be fixed there) and should be separated from unit selection, with a risk of web-compat problems like the NNBSP one. [EAO](../../people/EAO.md) wanted a proper SI-prefix formatting solution in the meantime, and [RGN](../../people/RGN.md) found special-casing SI units brittle (e.g. "100K s" versus "100 Ks"). Open: [EAO](../../people/EAO.md) wants to discuss it under [Stable Formatting](../../proposals/stable-formatting.md) and [SFC](../../people/SFC.md) with the CLDR design group.
