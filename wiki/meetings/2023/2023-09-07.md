## Overview

Moderated by [SFC](../../people/SFC.md) (co-moderator). TG2 approved two [Intl.DurationFormat](../../proposals/intl-durationformat.md) normative PRs (#172 moving `numberingSystem` before `style` in `resolvedOptions`, #167 omitting an `undefined` `fractionalDigits`), approved sending #780 (locale-set fingerprinting note) to TG1, and tentatively approved #788 (UTC offset time zones, minute precision) pending updated spec text. [EAO](../../people/EAO.md)'s new root-locale proposal was discussed at length and, after renaming to [Stable Formatting](../../proposals/stable-formatting.md), judged ready for Stage 1 at TG1 with open questions about whether it belongs in ECMA-402. Intl.MessageFormat API questions were raised, with an incubator call proposed. Three Intl Locale Info issues were settled (#73 keep names, #71 keep `undefined`, #68 tentatively option C). Several remarks are attributed to "LFS" in the notes; this is normalised to [LAF](../../people/LAF.md).

## Normative: Move numberingSystem before style in resolvedOptions

- wiki: [Intl.DurationFormat](../../proposals/intl-durationformat.md)
- proposal: [proposal-intl-duration-format#172](https://github.com/tc39/proposal-intl-duration-format/pull/172)

[FYT](../../people/FYT.md) explained that `[[NumberSystem]]` is currently read last, whereas the rest of ECMA-402 reads options in output order; the order was changed accidentally in another PR and a merged PR reverts that. Anba suggests placing it just below `locale`. [SFC](../../people/SFC.md) supported consistency (locale extensions should appear next to `locale`), and [LAF](../../people/LAF.md), [BAN](../../people/BAN.md), [DLM](../../people/DLM.md) and [YSZ](../../people/YSZ.md) gave explicit +1. It needs a TG1 update, which [SFC](../../people/SFC.md) offered to give if the champion cannot. **Conclusion: Approved by this group.**

## Normative: Don't output "fractionalDigits" when the value is undefined #167

- wiki: [Intl.DurationFormat](../../proposals/intl-durationformat.md)
- proposal: [proposal-intl-duration-format#167](https://github.com/tc39/proposal-intl-duration-format/pull/167)

The PR contains many editorial changes plus one normative change: `resolvedOptions()` no longer emits the `fractionalDigits` key when its value is `undefined`. [FYT](../../people/FYT.md) strongly supported it (the current spec forces awkward implementation); existing test262 tests will need updating. [JGT](../../people/JGT.md) asked about user impact, and [FYT](../../people/FYT.md) and [RGN](../../people/RGN.md) answered that it is tiny (a prototype lookup instead of a guaranteed `undefined`, consistent with other resolved options). [LAF](../../people/LAF.md), [BAN](../../people/BAN.md), [JGT](../../people/JGT.md) and [YSZ](../../people/YSZ.md) supported. **Conclusion: Approved by this group.**

## New proposal: Define the behavior and properties of the "und" root locale

- proposal: [proposal-intl-root-locale](https://github.com/eemeli/proposal-intl-root-locale)

[EAO](../../people/EAO.md) presented the problem: Intl formatting is implementation-defined, and there is no stable way to get e.g. ISO 8601 output (people resort to hacks such as formatting in Swedish). The proposal would define a fully specified locale (`"und"`, or the rarer `"zxx"`, possibly with `null` as an alias). [SFC](../../people/SFC.md) and [YSZ](../../people/YSZ.md) saw strong motivation (testing, ecosystem stability; `en` is not stable across platforms), and [JGT](../../people/JGT.md) preferred `"zxx"` since `"und"` already has meaning. [FYT](../../people/FYT.md) and [ZB](../../people/ZB.md) questioned whether this belongs in ECMA-402, arguing the real gap is in ECMA-262 and the solution should live outside Intl. Naming was settled on "[Stable Formatting](../../proposals/stable-formatting.md)", leaving the relationship to ECMA-402 (and to Collator) as Stage 1 questions. [SFC](../../people/SFC.md) said [EAO](../../people/EAO.md) is good to move to Stage 1 with these caveats; [EAO](../../people/EAO.md) will refactor the text and may need extra time at TG1 in Tokyo.

## Intl.MessageFormat Stage 1 Update

- proposal: [proposal-intl-messageformat](https://github.com/tc39/proposal-intl-messageformat)
- slide: [link](https://docs.google.com/presentation/d/15lwZipk0k5pMscSBbEPpMySsnM_qd4MOo_NqmmKyS-Q/edit?usp=sharing)

[EAO](../../people/EAO.md) presented the reworked API (a single message, `format()`/`formatToParts()`, `resolvedOptions`, warnings rather than throws by default) and asked for help on API questions: how to format compound values (e.g. number plus currency), and how `formatToParts()` should represent parts that themselves contain parts or non-string values. [FYT](../../people/FYT.md) wanted constructor arguments and a locale list consistent with other ECMA-402 constructors; [RGN](../../people/RGN.md) pointed to `formatRangeToParts`, which keeps a flat array with a `source` property, as prior art. [SFC](../../people/SFC.md) was happy with the direction and proposed an incubator call ([RGN](../../people/RGN.md), [SFC](../../people/SFC.md), [ZB](../../people/ZB.md), [BAN](../../people/BAN.md)?) to work through details. No formal decision.

## Normative: Added note about sets of locales for web browser implementations needing to not change as a result of user behaviour #780

- proposal: [ecma402#780](https://github.com/tc39/ecma402/pull/780)

[LAF](../../people/LAF.md) asked about the fingerprinting impact; [BAN](../../people/BAN.md) noted that i18n and privacy is fundamentally difficult. MCM asked whether the locale "fake download" would be observable; [SFC](../../people/SFC.md) said the normative text is about making users not distinguishable and the mechanism is not settled since no browser implements it. [DLM](../../people/DLM.md) was happy to send it to plenary. **Conclusion: Okay to send to TG1.**

## Normative: Allow UTC offset time zones #788

- proposal: [ecma402#788](https://github.com/tc39/ecma402/pull/788)

Following the June discussion, Temporal reduced offset time zone precision to minutes ([JGT](../../people/JGT.md)), so the PR, which still works in nanoseconds, needs updating; [RGN](../../people/RGN.md) will add a constraint (copied from Temporal) rejecting sub-minute offsets in the `ParseTimeZoneOffsetString` call. [LAF](../../people/LAF.md) raised historical sub-minute offsets (e.g. Paris before 1900), which [JGT](../../people/JGT.md) said are covered by named time zones, not offset time zones. [SFC](../../people/SFC.md) also confirmed `timeZoneName` formatting works as expected (implementation-defined). [JGT](../../people/JGT.md) suggested checking how much ICU/CLDR would need to change, and [FYT](../../people/FYT.md) asked for illustrative code in the PR description. **Conclusion: Tentatively approved, pending updated spec text** (to be reviewed in the context of TG1).

## Possible forward-compatibility issue in Intl.Locale.prototype.getTimeZones()? #73

- proposal: [proposal-intl-locale-info#73](https://github.com/tc39/proposal-intl-locale-info/issues/73)

Anba asked whether `getTimeZones` should become `getTimeZoneIDs` (and `getCalendars` `getCalendarIDs`) to avoid collisions with UTS 35 concepts. [SFC](../../people/SFC.md), [RGN](../../people/RGN.md) and [JGT](../../people/JGT.md) favoured internal ECMA-402 consistency (`TimeZone`/`Calendar` naming, with the pre-existing `timeZones`/`calendar` getters) over aligning with Temporal, and collisions will be avoided by design. **Conclusion: Close the issue** (keep `getTimeZones()` and `getCalendars()`).

## Consistent "region" subtag requirements for getTimeZones() and getWeekInfo()/getHourCycles() #71

- proposal: [proposal-intl-locale-info#71](https://github.com/tc39/proposal-intl-locale-info/issues/71)

Anba suggested maximising the locale when no region is given. [SFC](../../people/SFC.md) first proposed returning a single-element `["UTC"]` array; [JGT](../../people/JGT.md) preferred an empty array or `undefined` and disliked `UTC`. After discussion, [SFC](../../people/SFC.md) concluded that guessing is a footgun and that `undefined` surfaces the problem to the user; [LAF](../../people/LAF.md) supported `undefined`. **Conclusion: Keep `undefined`.**

## Add support for -u-fw and other Unicode extensions that could impact the result #68

- proposal: [proposal-intl-locale-info#68](https://github.com/tc39/proposal-intl-locale-info/issues/68)

Discussed in the overflow time. TG1 wanted the first-day-of-week getter to return numbers rather than BCP 47 strings, so the question is what the option accepts (strings, numbers, and `0`). [SFC](../../people/SFC.md) narrowed the options to fully lenient (C) or fully strict (D), noting that recent practice has been lenient; [JGT](../../people/JGT.md) and [LAF](../../people/LAF.md) supported C. **Conclusion: Tentative agreement on option C.**
