## Overview

Moderated by [SFC](../../people/SFC.md) and [USA](../../people/USA.md) (co-moderators). TG2 recorded approval of three normative PRs to bring to the next TG1 meeting (#1074 `getNumberingSystems`, #1072 `getCollations`, #1051 `WeekInfoOfLocale`) and looked at an editorial `GetOption` change (#1068). Anba's #1059 was judged too broad for a normative PR and should become a proposal on region overrides (`-u-rg`). Two temperature checks (`identityFallback` for `formatRange`, `Intl.PersonNameFormat`) gave feedback but no commitments, and the group disagreed on whether Intl Sequence Units should support time units.

## Updates from the Editors

[RGN](../../people/RGN.md) reported little news: aligning with ECMA-262 on alias naming reforms, to be merged before the next meeting. [SFC](../../people/SFC.md) asked whether the 2026 edition (to be approved at the GA later in the month) is ready; [RGN](../../people/RGN.md) believes so.

## Updates from the MessageFormat Working Group

[EAO](../../people/EAO.md): one meeting, nothing significant. Some work is blocked by semantic skeletons for date/time still being in tech preview, so possibly targeting version 50 rather than 49.

## Updates from Implementers

[YSZ](../../people/YSZ.md) (Apple): the Temporal implementation is now working, including time zone canonicalization, and the Status Wiki was updated. [SFC](../../people/SFC.md) noted the wiki table needs updating (Temporal and Intl Era/Month Codes are now Stage 4; Keep Trailing Zeros is Stage 3 and needs links to tests and implementations; Sequence Units is missing) and that implementation status should be kept up to date.

## Updates from the W3C i18n Group

[EAO](../../people/EAO.md): the W3C definition of "locale" is being changed from "a locale identifier" to a set of preferences keyed by an identifier. [RGN](../../people/RGN.md) noted ECMA-402 uses "locale" without defining it. No action needed.

## Normative: Allow Locale.p.getNumberingSystems to return >1 item

- proposal: [ecma402#1074](https://github.com/tc39/ecma402/pull/1074)

[SFC](../../people/SFC.md)'s bug: `getNumberingSystems` returned only the first CLDR numbering system, so [PFC](../../people/PFC.md)'s PR lets implementations return more than one entry (ordered by common use, returning a copy). [RGN](../../people/RGN.md) thought the suggested text slightly off but mostly good; [SFC](../../people/SFC.md), [DLM](../../people/DLM.md) and [YSZ](../../people/YSZ.md) found it fine. **Conclusion: TG2 approval, to be brought to the next TG1 meeting.**

## Normative: Avoid default locale fallback within Locale.p.getCollations()

- proposal: [ecma402#1072](https://github.com/tc39/ecma402/pull/1072)

With a host `LANG` such as `ko` or `zh`, `getCollations()` for `und` or an unknown language returned that host language's collations; it should return the root collations (only two). The PR matches by language prefix, as already done, and is analogous to the numbering-systems algorithm. [RGN](../../people/RGN.md) and [YSZ](../../people/YSZ.md) agreed it looks good, and [SFC](../../people/SFC.md) really liked it. **Conclusion: TG2 approval; [DLM](../../people/DLM.md) has time to check further.**

## Editorial: Revise GetOption to trigger a TypeError for absent mandatory options (potentially significant enough for collective review)

- proposal: [ecma402#1068](https://github.com/tc39/ecma402/pull/1068)

Editorial because no current call site is reachable (an earlier Temporal iteration used it, but Temporal now has its own `GetOption` and throws `RangeError`, which [RGN](../../people/RGN.md) considers inferior). [SFC](../../people/SFC.md) preferred dropping the enum variant that is not used and [RGN](../../people/RGN.md) will adjust the PR, including removing a leftover line. [SFC](../../people/SFC.md) and [YSZ](../../people/YSZ.md) approved, and [RGN](../../people/RGN.md) plans a Temporal PR (possibly after Temporal lands) to switch to `TypeError` for consistency.

## Normative: Synchronize RegionPreference and CanonicalUnicodeSubdivision with UTS 35 standards

- proposal: [ecma402#1059](https://github.com/tc39/ecma402/pull/1059)

The discussion turned to what validity means for the region override (`-u-rg`) subtag in UTS 35 (macro regions are not valid, `zz` handling is unclear) and to the fact that ECMA-402 only honours region overrides in `GetCalendars`/`GetHourCycles` (see [ecma402#370](https://github.com/tc39/ecma402/issues/370), still open). [SFC](../../people/SFC.md), [RGN](../../people/RGN.md) and [EAO](../../people/EAO.md) agreed that region overrides are a sweeping change: if supported anywhere they should be supported everywhere, and the `zz` and `usd`-without-`rg` cases need CLDR input. **Conclusion: this should not be a normative PR but a proposal; notes to be posted on the issue and a champion is needed (none volunteered yet).**

## Normative: Invoke RegionPreference during WeekInfoOfLocale

- proposal: [ecma402#1051](https://github.com/tc39/ecma402/pull/1051)

`RegionPreference` is already used for calendars and hour cycles but not for `WeekInfoOfLocale`, which looks like an oversight. [RGN](../../people/RGN.md) was willing to push this narrow fix ahead of the broader proposal, HJS noted the inconsistency in region lookup across getters, and [EAO](../../people/EAO.md) noted hour cycle can currently come out differently depending on the path. [SFC](../../people/SFC.md) considered it high priority for consistency with `Intl.DateTimeFormat`. **Conclusion: TG2 approval; other comments may be raised until the next TG1 meeting.**

## Examine the consequences of Henri's findings regarding the cessation of support for language subtags exceeding three characters in ECMA-402

- proposal: [ecma402#951](https://github.com/tc39/ecma402/issues/951)

HJS's use-counter data show the feature is used more than expected, so it is unclear whether it is legitimate use or garbage. The next step would be identifying the values (for example via HTTP Archive or additional counters designed within privacy policies), but HJS cannot take that on now; ICU4X is also in a holding pattern on whether to implement these. [SFC](../../people/SFC.md) noted the change is already in the ES2026 milestone. Open, no owner.

## Temperature check: Integration of identityFallback option in Intl.NumberFormat#formatRange

- proposal: [ecma402#1064](https://github.com/tc39/ecma402/issues/1064)

An ICU-derived `identityFallback` would let `formatRange` show a single value (or "approximately") when inputs are equal or round to the same output. [EAO](../../people/EAO.md) and [RGN](../../people/RGN.md) did not want equality tests on anything but formatted results and were not interested in the "approximately or single" mode, but were open to an opt-in fallback between range and single value. [SFC](../../people/SFC.md) will relay the feedback and considered it easy to champion.

## Temperature check: Advancing Intl.PersonNameFormat for culturally aware name formatting

- proposal: [ecma402#1061](https://github.com/tc39/ecma402/issues/1061)

[SFC](../../people/SFC.md) described the CLDR person-name formatting (UTS 35 chapter, ICU4J, a contributor-built ICU4X implementation, structured records). HJS, [RGN](../../people/RGN.md) and [EAO](../../people/EAO.md) asked for evidence of web developer demand (existing npm packages have low usage, no Android ICU implementation was found, structured input may not be available in applications); HJS suggested checking Apple's API (since iOS 15) for usage data. [SFC](../../people/SFC.md)'s view is that a well-documented Intl API could fix a problem developers do not yet recognise, and the group will reply to the issue author with these questions to strengthen the motivation.

## Evaluation of time unit support

- proposal: [proposal-intl-sequence-units#8](https://github.com/tc39/proposal-intl-sequence-units/issues/8)

[SFC](../../people/SFC.md)'s table of sanctioned combinable unit groups currently excludes time units: `DurationFormat` with `Temporal.Duration` already solves duration formatting, and mixes like day+hour or month+day raise time zone and calendar problems; [SFC](../../people/SFC.md) also does not want `Amount` to support them. [RGN](../../people/RGN.md) and [EAO](../../people/EAO.md) disagreed (Amount is defined in terms of CLDR `units.xml`, no normalization happens, and CLDR's data has `minute-and-second` and person-age preferences). [RGN](../../people/RGN.md) and [EAO](../../people/EAO.md) also asked to add `degree-arcminute-arcsecond` (e.g. coordinates), which [SFC](../../people/SFC.md) would prefer as a follow-on proposal. No consensus; discussion ended without a decision.
