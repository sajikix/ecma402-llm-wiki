## Overview

Moderated by [SFC](../../people/SFC.md) (co-moderator). TG2 approved three normative PRs against ECMA-402 (#1074 `getNumberingSystems`, #1097 `getWeekInfo().firstDay`, #1095 `%TypedArray%.prototype.toLocaleString`; the first two presented by [JMN](../../people/JMN.md) from [PFC](../../people/PFC.md)'s prepared text) and settled two [Intl Sequence Units](../../proposals/intl-sequence-units.md) design questions (throw on significant-digit rounding; array input instead of an object). [EAO](../../people/EAO.md) was put forward as a third ECMA-402 editor. Several long-standing issues were triaged: async locale-data loading (#434) was deprioritised. [RGN](../../people/RGN.md) spoke throughout but is not in the attendee list.

## PR #1074: Allow Locale.p.getNumberingSystems to return >1 item — Consensus on updated text distinguishing supported systems from those in common use.

- proposal: [ecma402#1074](https://github.com/tc39/ecma402/pull/1074)

A re-approval: [PFC](../../people/PFC.md)'s revision distinguishes numbering systems "supported" for a locale (ICU supports any base-10 system anywhere) from those "in common use", so `new Intl.Locale('en-US').getNumberingSystems()` should not list Malayalam digits. [SFC](../../people/SFC.md) noted this adds implementation-defined filtering data unlike `Collator` (which copies locale data as-is), while calendars already do this, and asked that the implementation-defined part be explicit. **Conclusion: TG2 approval.**

## PR #1097: Determine getWeekInfo().firstDay using First Day Overrides — Fallback priority resolution for calendar and region subtags.

- proposal: [ecma402#1097](https://github.com/tc39/ecma402/pull/1097)

Aligns `getWeekInfo().firstDay` with Unicode's first-day-of-week resolution ([PFC](../../people/PFC.md), read by [JMN](../../people/JMN.md)), with test262 coverage of the priority between constructor options and extension keywords (`-u-rg` beats the `region` option; `sd` only when it matches, then `ca`), and a hard-coded value for `-u-ca-iso8601` as in Temporal and Intl Era/Month Codes. [SFC](../../people/SFC.md) found the priorities matched expectations. **Conclusion: TG2 approval.**

## PR #1095: Define %TypedArray%.prototype.toLocaleString — Forwarding locales and options arguments to elements to match web reality.

- proposal: [ecma402#1095](https://github.com/tc39/ecma402/pull/1095)

ECMA-402 overrides `Array.prototype.toLocaleString` but never defined the analogous TypedArray method that ECMA-262 implies; [RGN](../../people/RGN.md)'s PR writes down what browsers already ship. [SFC](../../people/SFC.md) would prefer `toLocaleString` to use `ListFormat` (ecma402#422) but accepted matching web reality instead, and left a comment about the separator lookup that ECMA-262 does from the host locale. **Conclusion: TG2 approval.**

## Sequence Units Issue #14: Significant digit formatting is problematic with sequence units — Erroring on maximumSignificantDigits with non-decimal ratios.

- wiki: [Intl Sequence Units](../../proposals/intl-sequence-units.md)
- proposal: [proposal-intl-sequence-units#14](https://github.com/tc39/proposal-intl-sequence-units/issues/14)

Following [Amount](../../proposals/amount.md), which throws on significant-digit options, TG2 went stricter than [EAO](../../people/EAO.md)'s suggestion: `minimumSignificantDigits` should fail too, since splitting significant digits across units would need a brittle algorithm with no use case ([SFC](../../people/SFC.md)), and only `roundingPriority: "auto"` stays valid ([RGN](../../people/RGN.md)). **Conclusion: throw when the NumberFormat uses significant-digit rounding (`[[RoundingType]]` must be fraction-digit rounding); the exact order of operations is left to the PR.**

## Sequence Units Issue #16: Use an array instead of an object — Alignment with proposal-amount on input structure for format().

- wiki: [Amount](../../proposals/amount.md), [Intl Sequence Units](../../proposals/intl-sequence-units.md)
- proposal: [proposal-intl-sequence-units#16](https://github.com/tc39/proposal-intl-sequence-units/issues/16)

[Amount](../../proposals/amount.md) has largely settled on array input (proposal-[amount](../../proposals/amount.md)#118), which avoids odd behaviour of an object keyed by unit ID; the array must match the sequence unit. [RGN](../../people/RGN.md) and [JMN](../../people/JMN.md) agreed. **Conclusion: TG2 approves switching to an array.**

## Async APIs for Intl loading #434

- proposal: [ecma402#434](https://github.com/tc39/ecma402/issues/434)

Async loading of extra locale data (locales, units, emoji annotations) has been open since 2020. [SFC](../../people/SFC.md) now recommends deprioritising it: the timing-attack/fingerprinting concerns make privacy alignment hard, and data that is motivated for the web should simply be shipped. [RGN](../../people/RGN.md), [CDA](../../people/CDA.md) and [YSZ](../../people/YSZ.md) agreed not to reject but not to pursue it now.

## Cyclic year doesn't show up in resolvedOptions #816

- proposal: [ecma402#816](https://github.com/tc39/ecma402/issues/816)

Still reproducible after years; TG2 agreed it is a bug and to take Anba's suggested fix.

## Allow compact notation to depend on style

- proposal: [ecma402#810](https://github.com/tc39/ecma402/issues/810)

Compact notation with units (e.g. "10k meters", bytes) renders without the expected space. [SFC](../../people/SFC.md) and [RGN](../../people/RGN.md) judged it mostly a CLDR data bug (a prefix like "k" should introduce a space), but ECMA-402 must make sure it can accommodate a fix without being overly opinionated about output.
